# 인터넷 라디오 패널 디자인 명세

이 문서는 S.tand의 **인터넷 라디오 패널 기능만** iOS와 동일하게 Android에 구현하기 위한 전달 명세다.

## 1. 기능 범위

- 앱에 방송국이나 스트림 주소를 기본 제공하지 않는다.
- 사용자가 패널 편집 모드에서 직접 입력한 방송 이름과 HTTPS 스트림 주소 하나를 기기에만 저장한다.
- iOS Safari 또는 Android 공유 시트에서 사용자가 선택한 HTTPS URL을 주소 입력 초안으로 가져올 수 있다. 사용자가 설정 화면에서 `저장`하기 전에는 기존 주소를 변경하지 않는다.
- 라디오는 설정 버튼이나 하단 버튼 배열에 넣지 않고 시계·날씨와 같은 독립 정보 패널로 표시한다.
- 주소를 삭제하면 일반 홈에서 패널을 숨기되 세로·가로 위치와 크기는 보존한다.
- 원본 서버에서 사용자 기기로 직접 재생한다. S.tand 서버를 통한 프록시, 재송신, 변환, 다운로드, 녹음, 영구 캐시는 구현하지 않는다.
- 포그라운드에서만 재생한다. 앱이 비활성 또는 백그라운드 상태가 되면 즉시 정지하며 자동 재개하지 않는다.
- 방송 검색, 추천, 디렉터리, 공유, 방송 로고, 앨범 아트, 곡 메타데이터는 범위 밖이다.

## 2. 홈 패널 배치와 규격

| 항목 | 명세 |
|---|---|
| 배치 | 정보 패널 캔버스의 독립 패널, 하단 버튼 슬롯과 무관 |
| 기준 크기 | 144×60dp, 종횡비 고정 |
| 기본 변환 | `x=0.26`, `y=0.215`, `scale=0.75` |
| 위치 좌표 | 화면 중심 기준, `x`는 캔버스 폭·`y`는 높이로 정규화 |
| 크기 범위 | 30~200%, 중심 고정 균등 확대·축소 |
| 모서리 | 연속형 13dp |
| 내부 좌우 여백 | 11dp |
| 아이콘 | 24dp 프레임 안에 17dp, semibold |
| 제목 | 10.5sp, semibold, 1줄, 왼쪽 정렬 |
| 상태 | 8.5sp, medium, 1줄, 왼쪽 정렬 |
| 전경 | 흰색 78% |
| 상태 전경 | 흰색 52% |
| 배경 상단 | 흰색 9.5% |
| 배경 하단 | 흰색 5.2% |
| 외곽선 | 흰색 8%, 1dp |
| 플립 분할선 | 중앙 2dp 투명 간격 |

세로·가로의 `x`, `y`, `scale`은 각각 저장한다. 회전해도 플레이어를 다시 만들지 않고 현재 방향의 패널 변환만 적용한다. 라디오 등록·삭제는 `controlOrder`와 하단 버튼 줄 수를 절대 바꾸지 않는다. 패널이 30%로 축소돼도 터치·접근성 영역은 패널 중심 기준 iOS 44×44pt, Android 48×48dp 이상을 유지한다.

Android 아이콘은 Material Symbols Rounded를 우선 사용한다.

| 상태 | iOS SF Symbol | Android Material Symbol |
|---|---|---|
| 대기·실패 | `radio.fill` | `radio` |
| 연결 중 | `antenna.radiowaves.left.and.right` | `settings_input_antenna` |
| 재생 중 | `stop.circle.fill` | `stop_circle` |
| 편집 | `pencil` | `edit` |

## 3. 홈 패널 상태

| 상태 | 패널 상태 문구 | 아이콘 | 탭 동작 |
|---|---|---|---|
| `idle` | `재생` | `radio` | 연결 시작 |
| `loading` | `연결 취소` | `settings_input_antenna` | 연결 취소·오디오 세션 반납 |
| `playing` | `감지·녹음 중지` | `stop_circle` | 재생 정지·감시 조건부 재개 |
| `failed` | `연결 실패 · 다시 듣기` | `radio` | 같은 주소로 다시 연결 |

라디오가 `loading` 또는 `playing`이면 화면 상단에 `라디오 재생 중 · 소리 감지와 녹음은 일시 중지됨` 배너를 표시한다. 아이콘은 `radio`이며 기존 반투명 캡슐 배너 스타일을 사용한다.

접근성은 패널 전체를 하나의 버튼으로 읽고 방송 이름과 상태를 함께 알린다. 힌트는 상태별로 다음과 같이 제공한다.

- 대기·실패: `등록한 인터넷 라디오를 재생합니다.`
- 연결 중: `인터넷 라디오 연결을 취소합니다.`
- 재생 중: `인터넷 라디오를 끄고 소리 감지와 녹음을 다시 시작합니다.`

## 4. 편집 모드

미등록 상태에서는 일반 홈에 라디오를 표시하지 않지만 패널 편집 화면에는 기본 위치에 점선 테두리의 자리표시자를 표시한다. 자리표시자는 `인터넷 라디오`와 `HTTPS 주소 등록`, 주황색 편집 아이콘을 보여 준다.

- 본체 드래그: 하단 슬롯이나 그리드 없이 자유 이동하며 다른 패널과 겹칠 수 있다.
- 핀치: 패널 중심을 유지하며 30~200% 확대·축소한다.
- 왼쪽 위 26×26dp 손잡이 드래그: 핀치와 같은 비율로 크기를 조절한다.
- 중앙 자석: 중심 오차가 렌더링된 패널 폭 또는 높이의 5% 이내일 때 해당 중앙선에 맞추고 진입 시 한 번 진동한다.
- 편집 아이콘 또는 패널 탭: 재생하지 않고 주소 편집 화면을 연다.
- `패널 초기화`: 현재 방향의 시계·날씨·상태·배터리·라디오를 포함한 모든 패널 위치와 크기를 기본값으로 되돌린다. 라디오 주소와 재생 설정은 변경하지 않는다.

편집 안내는 `패널 이동·크기 조절 · 라디오 연필을 눌러 주소 편집`으로 표시한다. 설정 버튼과 하단 버튼 순서 편집 화면에는 라디오 주소 등록 UI를 두지 않는다.

## 5. 주소 편집 화면

화면 제목은 `인터넷 라디오`이며 상단에 `취소`, `저장`을 둔다.

입력 항목:

1. `이름 (선택)`
   - 앞뒤 공백 제거
   - 빈 값이면 `인터넷 라디오`
   - 저장 시 최대 30자
2. `https://…`
   - URL 키보드
   - 자동 대문자·자동 수정 끄기
   - 앞뒤 공백 제거
   - 최대 2,048자

검증 규칙:

- 빈 주소 거부: `라디오 주소를 입력해 주세요.`
- HTTPS 이외의 스킴 거부: `https://로 시작하는 안전한 스트림 주소만 사용할 수 있습니다.`
- 호스트가 없는 주소 거부: `서버 주소를 확인해 주세요.`
- 사용자명·비밀번호가 URL에 포함된 주소 거부: `아이디나 비밀번호가 포함된 주소는 저장할 수 없습니다.`
- 길이 초과 거부: `라디오 주소가 너무 깁니다.`

검증 오류는 입력 영역 바로 아래에 주황색 경고 아이콘과 한 줄 이상의 보조 문구로 표시한다. 저장된 주소가 있으면 하단에 빨간색 `등록 주소 삭제` 버튼을 제공한다.

반드시 표시할 안내 문구:

> 직접 이용 권한을 확인한 합법적인 HTTPS 스트림 주소만 등록해 주세요. 주소는 이 기기에만 저장되며 방송을 저장하거나 중계하지 않습니다.

재생 정책 안내:

- `소리 감지와 수면 녹음은 일시 중지됩니다.`
- `기기 움직임 감지는 계속됩니다.`

## 6. 재생·오디오 정책

상태 흐름은 다음과 같다.

`idle → loading → playing → idle`

오류가 나면 `loading/playing → failed`, 다시 탭하면 `failed → loading`이다. 연결을 30초 안에 시작하지 못하면 `failed`로 전환한다.

라디오 시작 순서:

1. 감시 중단 사유에 `internetRadio` 추가
2. 마이크 캡처와 진행 중 후보 녹음 정상 종료
3. 재생용 오디오 포커스 획득
4. 스트림 연결·재생

라디오 정지·실패 순서:

1. 플레이어 정지 및 미디어 항목 해제
2. 재생용 오디오 포커스 반납
3. 감시 중단 사유에서 `internetRadio` 제거
4. 매이트 모드·자동 돌봄 실행 중·앱 활성 상태일 때만 마이크 감시 재개

라디오가 연결 중이거나 재생 중일 때:

- 마이크 기반 주변 소리 학습, 소리 기반 화들짝 반응, 코골이·잠꼬대 후보 녹음을 모두 중지한다.
- 기기 센서 기반 움직임 감지는 계속한다.
- 라디오와 로컬 수면 녹음 재생은 동시에 실행하지 않는다. 녹음 목록을 열기 전에 라디오를 먼저 정지한다.
- 전화·다른 앱의 오디오 인터럽션, 오디오 서비스 재설정, 유선·Bluetooth 출력 분리 시 즉시 정지한다. 출력 분리 후 스피커로 자동 전환하거나 자동 재생하지 않는다.

## 7. 브라우저 공유로 주소 가져오기

공유 대상 이름은 `S.tand 라디오`다. 브라우저가 전달한 URL 한 개만 받으며 웹페이지 HTML을 분석해 숨은 스트림을 찾거나, 네트워크 HEAD 요청으로 형식을 추측하지 않는다.

공통 흐름:

1. 사용자가 Safari 또는 Chrome에서 공유를 누르고 `S.tand 라디오`를 선택한다.
2. `웹페이지가 아니라 라디오가 직접 재생되는 합법적인 HTTPS 주소여야 합니다` 안내와 전체 주소를 보여 준다.
3. 사용자가 `라디오 주소로 가져오기`를 누른다.
4. 라디오 편집 화면을 열어 URL 필드에 주소를 미리 입력한다.
5. 기존 등록 주소는 `저장`을 누르기 전까지 유지하고, `취소`하면 아무 설정도 바꾸지 않는다.

iOS는 Share Extension이 본 앱을 강제로 열지 않는다. App Group `group.com.armsone.stand`의 1건짜리 pending 저장소에 검증된 초안을 두고, 사용자가 S.tand를 다음에 열면 편집 화면을 자동 표시한다. 저장 또는 취소할 때 pending 값을 지우며, 그 전에 앱이 종료되면 다음 실행에서 다시 제안한다. 연속해서 다른 주소를 공유하면 가장 최근의 유효한 주소가 우선한다.

Android는 `ACTION_SEND`와 MIME `text/plain`을 받는 전용 `RadioShareReceiverActivity`를 사용한다. `EXTRA_TEXT`의 URL 한 개만 검증하고 라디오 편집 화면으로 전달한다. 브라우저 역할로 오인되지 않도록 `ACTION_VIEW` 필터는 등록하지 않는다. Receiver Activity는 exported 상태이므로 입력을 신뢰하지 말고 앱 내부와 같은 HTTPS·호스트·자격 증명 검증을 다시 수행한다.

## 8. Android 구현 매핑

- 플레이어: AndroidX Media3 `ExoPlayer`
- 오디오 포커스: `AudioManager`와 Media3 audio attributes 사용
- 권장 attributes: `USAGE_MEDIA`, `CONTENT_TYPE_MUSIC`
- 포커스 손실 또는 `AUDIO_BECOMING_NOISY`: 즉시 정지, 자동 재개 금지
- 앱 `onStop`: 즉시 정지하고 플레이어·오디오 포커스 해제
- 저장: Preferences DataStore에 `displayName`, `urlString`과 방향별 `radioPanelX`, `radioPanelY`, `radioPanelScale` 저장
- 마이그레이션: 과거 `controlOrder`의 `radio`·`orientation`·`aiShot` 값은 무시하고, 패널 좌표가 없으면 기본 변환을 적용
- 네트워크 보안: cleartext 비활성 유지, HTTPS만 앱 레벨에서 재검증
- 지원 대상: Media3가 직접 재생하는 HTTPS MP3/AAC 스트림과 HLS(`.m3u8`)
- 이번 범위에서 미지원: `.m3u`·`.pls` 방송목록 파싱, 인증 URL, DRM, 사용자 지정 HTTP 헤더, 백그라운드 Service, 알림·잠금화면 미디어 컨트롤

Android 상태 객체는 최소한 아래 값을 노출한다.

```kotlin
sealed interface InternetRadioState {
    data object Idle : InternetRadioState
    data object Loading : InternetRadioState
    data object Playing : InternetRadioState
    data class Failed(val message: String) : InternetRadioState
}
```

플레이어는 화면 Composable이 아니라 앱 범위 ViewModel 또는 전용 coordinator가 소유한다. 화면 재구성이나 회전으로 플레이어가 중복 생성되지 않아야 한다.

## 9. 완료 조건

- 신규 설치와 초기화 후 라디오 주소·방송국이 미리 들어 있지 않다.
- 미등록 상태에서는 일반 홈에 라디오가 없고 패널 편집 화면에만 주소 등록 자리표시자가 보인다.
- 유효한 주소를 저장하면 일반 홈의 세로·가로 캔버스에 라디오 패널이 각각 한 개만 보인다.
- 라디오 등록·삭제·이동은 하단 버튼 순서와 줄 수를 바꾸지 않는다.
- 세로·가로 위치·크기가 독립 저장되고 자유 이동과 30~200% 조절 결과가 재실행 후 복원된다.
- 설정 버튼과 하단 버튼 순서 편집 화면에는 라디오 주소 등록 UI가 없다.
- 편집 모드에서 패널을 탭하거나 크기를 조절해도 재생이 시작되지 않는다.
- 이름 공백 입력은 `인터넷 라디오`로 저장되고 주소 공백은 제거된다.
- HTTP, 파일 URL, 호스트 없는 URL, 자격 증명이 포함된 URL은 저장되지 않는다.
- 등록 주소 삭제 시 재생이 멈추고 일반 홈에서 패널이 숨겨지며 배치 변환은 보존된다.
- 연결·재생 중 마이크 아이콘과 수면 녹음이 꺼지고 움직임 감지는 유지된다.
- 정지·실패 후 조건이 맞을 때만 마이크 감시가 재개된다.
- 녹음 목록 진입, 앱 백그라운드, 오디오 포커스 손실, 헤드폰 분리 시 라디오가 정지한다.
- 빠른 반복 탭, 네트워크 끊김, 잘못된 스트림, 화면 회전에서 중복 재생·오디오 포커스 누수·감시 중단 사유 누수가 없다.
- TalkBack에서 30% 크기에도 최소 48×48dp 대상으로 패널 이름, 상태, 동작 힌트가 한 요소로 읽힌다.
